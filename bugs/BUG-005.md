# BUG-005 — Лічильник перемикань реле `cycles` росте на 2 за одне перемикання

| Поле | Значення |
|---|---|
| Версія, де знайдено | 2.1.0 |
| Відтворюється в 2.3.0 | **Ні — виправлено.** Кожне перемикання реле на 2.3.0 коректно додає +1 до `cycles` (підтверджено й окремо під час OTA-циклу: `cycles 108 → 110` після низки ручних перемикань, без подвоєння) |
| Severity | Major |
| Priority | P2 (Medium) |
| Вимога PRD | RL-2: «`cycles N` — кількість перемикань за весь час (одне перемикання on або off = +1). Лічильник зберігається в NVS»; RL-6: знос контактів, ресурс 100000 перемикань |
| Тип | Некоректний облік / дані |
| Відтворюваність | 3/3 (+ ручне спостереження) |

## Передумови
- DUT 2.1.0, `login` виконано, реле вимкнене.

## Кроки відтворення
1. `relay status` — записати `cycles N`.
2. `relay on`, потім `relay status`.
3. Почекати >1 с (ліміт E602), `relay off`, `relay status`.

## Очікуваний результат
`cycles`: N → N+1 після `on` → N+2 після `off`.

## Фактичний результат
Кожне перемикання додає 2:

```text
relay status -> [VALVE] closed, auto off, cycles 52
relay on     -> [VALVE] OPEN (command)
relay status -> [VALVE] OPEN, auto off, cycles 54      (+2)
relay off    -> [VALVE] CLOSED (command)
relay status -> [VALVE] closed, auto off, cycles 56    (+2)
```

Те саме при перемиканні через `logout` (`CLOSED (logout)` також +2).

## Вплив
Лічильник вдвічі завищує знос контактів: `relay health` показує знос, у 2 рази більший за реальний, і ресурс 100000 вичерпується «передчасно».
