# BUG-001 — `health interval 300` відхиляється, хоча 300 входить у допустимий діапазон

| Поле | Значення |
|---|---|
| Версія, де знайдено | 2.1.0 |
| Відтворюється в 2.3.0 | **Ні — виправлено.** `health interval 300` приймається коректно (автотест `test_health_interval_range[300-None]` зелений на 2.3.0) |
| Severity | Minor |
| Priority | P3 (Medium) |
| Вимога PRD | HL-3: `health interval <10-300>` — «10 і 300 включно (E902 поза діапазоном)» |
| Тип | Функціональний, межа діапазону (off-by-one) |
| Відтворюваність | 3/3 |

## Передумови
- DUT 2.1.0 після `erase-flash`, Wi-Fi підключено, `register` виконано.
- `login <login> <password>` успішний, стан 1 NORMAL.

## Кроки відтворення
1. Виконати `health interval 300`.
2. Для порівняння виконати `health interval 299` і `health interval 10`.

## Очікуваний результат
Значення 300 приймається (HL-3: «10 і 300 включно»), інтервал автозвіту стає 300 с. `E902` видається тільки для значень поза 10–300.

## Фактичний результат
Команда відхилена з кодом `E902`, а повідомлення прошивки саме стверджує, що 300 дозволено:

```text
TX: health interval 300
RX: E (11199) sentry: E902 interval must be 10-300 s
```

Прошивка суперечить власному повідомленню: діапазон «10-300» оголошено, але верхня межа не приймається. Інтервал лишається 30 с.
