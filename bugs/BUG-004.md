# BUG-004 — EMERGENCY вмикається зі стану DEBUG, хоча дозволений лише з VERBOSE

| Поле | Значення |
|---|---|
| Версія, де знайдено | 2.1.0 |
| Відтворюється в 2.3.0 | **Ні — виправлено.** `state 2` → `state 4` (або `state emergency`) коректно дає `E302` на 2.3.0 |
| Severity | Major |
| Priority | P1 (High) |
| Вимога PRD | ST-2: «EMERGENCY можна увімкнути тільки з 3 VERBOSE. З будь-якого іншого стану — `E302 EMERGENCY can be entered only from 3 VERBOSE (now N NAME)`, стан не змінюється. Це правило однакове для команди і кнопок» |
| Тип | Логіка станів, обхід обмеження |
| Відтворюваність | 3/3 (команда `state 4` і `state emergency`) |

## Передумови
- DUT 2.1.0, Wi-Fi підключено, `login` виконано, стан 1 NORMAL.

## Кроки відтворення
1. `state 2` (або `state debug`) — перехід у DEBUG.
2. `state 4` (або `state emergency`).
3. Для контролю: повторити з NORMAL (`state 1` → `state 4`).

## Очікуваний результат
Крок 2: `E302 EMERGENCY can be entered only from 3 VERBOSE (now 2 DEBUG)`, стан лишається DEBUG.

## Фактичний результат
З DEBUG пристрій входить в EMERGENCY і блокується (вийти можна лише `reboot`):

```text
TX: state emergency
RX: I (12603) sentry: [DBG] cmd 'state' args 'emergency' need 2
    W (12603) sentry: [STATE] 2 DEBUG -> 4 EMERGENCY (by command)
    E (12603) sentry: [EMERGENCY] EMERGENCY SURFACING. Module locked. ...Exit: reboot only
```

Із NORMAL правило працює правильно: `E302 ... (now 1 NORMAL)`. Дефект стосується саме стану DEBUG.

## Вплив
EMERGENCY означає аварійне спливання і блокування модуля. Захист від випадкового входу («тільки з VERBOSE» — тактичний режим) обходиться через DEBUG. Помилковий вхід необоротний без перезавантаження.
