# BUG-006 — Зміна пароля (`passwd`) не зберігається: після reboot знову діє старий пароль

| Поле | Значення |
|---|---|
| Версія, де знайдено | 2.1.0 |
| Відтворюється в 2.3.0 | **Ні — виправлено.** `passwd` на 2.3.0 коректно зберігається в NVS: старий пароль відхиляється, новий працює після reboot. Також перевірено, що сам факт OTA (2.1.0→2.3.0 і цикл 2.3.0⇄2.1.0) не скидає початковий зареєстрований пароль — login з оригінальними обліковими даними успішний після кожного переходу |
| Severity | Critical (безпека: ротація пароля не діє) |
| Priority | P1 (High) |
| Вимога PRD | AU-5: «`passwd` змінює пароль профілю **назавжди** (NVS): новий пароль працює після logout, reboot і OTA, старий — більше ні»; OTA-10 |
| Тип | Втрата даних / безпека |
| Відтворюваність | 3/3 |

## Передумови
- DUT 2.1.0, профіль зареєстровано з паролем `Pass1234`, `login` виконано.

## Кроки відтворення
1. `passwd Pass1234 NewPass99` → `[AUTH] password changed`.
2. `logout`; `login <login> Pass1234` — очікувано відхилено; `login <login> NewPass99` — вхід.
3. `reboot`, після старту `reconnect`.
4. `login <login> Pass1234` (старий пароль).

## Очікуваний результат
Після reboot старий пароль не працює (`E209`), новий працює.

## Фактичний результат
До reboot поведінка коректна (кроки 1–2: старий — `E209`, новий — вхід). Після reboot **старий пароль знову приймається**, а новий — ні:

```text
TX: login qa_swm Pass1234        (після reboot)
RX: I [AUTH] operator qa_swm on watch, console 2       <- старий пароль працює
TX: passwd NewPass99 Pass1234
RX: E215 old password is wrong                          <- нового пароля вже немає
```

Тобто зміна живе лише в RAM і втрачається при перезавантаженні.

## Вплив
Користувач вважає, що змінив пароль (наприклад, після підозри на компрометацію), але після будь-якого перезавантаження (втрата живлення, аварійний reboot, OTA) знову діє старий, можливо скомпрометований пароль. Це порушує вимогу безпеки і створює хибне відчуття захищеності.
