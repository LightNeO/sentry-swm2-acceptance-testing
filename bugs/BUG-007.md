# BUG-007 — У стані EMERGENCY команда `state` відповідає, хоча її немає в списку дозволених

| Поле | Значення |
|---|---|
| Версія, де знайдено | 2.1.0 |
| Відтворюється в 2.3.0 | **Так — не усунена.** `state` без аргументу в EMERGENCY і на 2.3.0 відповідає нормально, замість `E005`/`E001` |
| Severity | Trivial / Minor (спірне: лише читання стану) |
| Priority | P4 (Low) |
| Вимога PRD | ST-3: «В EMERGENCY дозволені **тільки**: `help`, `status`, `whoami`, `version`, `health now`, `alert list` (з 2.3.0), `reboot`. Будь-яка інша команда — E005 / E001 і температура драйвера росте» |
| Тип | Невідповідність специфікації |
| Відтворюваність | 3/3 |

## Передумови
- DUT 2.1.0, `login` виконано, стан EMERGENCY (`state 3` → `state 4`).

## Кроки відтворення
1. У EMERGENCY виконати `state` (без аргументів).
2. Для порівняння: `state 1` → `E304`; `lamp on` → `E005`.

## Очікуваний результат
`E005 'state' blocked in EMERGENCY` + ріст температури драйвера (як для інших команд поза списком).

## Фактичний результат
Команда виконується і друкує стан:

```text
TX: state
RX: I (10273) sentry: state: 4 EMERGENCY
    I (10273) sentry:   1 normal (patrol) | 2 debug (maintenance) | 3 verbose (tactical) | 4 emergency (surfacing, only from 3)
```

Температура драйвера при цьому не росте (на відміну від `lamp on`, `relay on`, `scan` тощо).

## Докази
- `logs/v2.1.0/repro_batch2_run1…3/test_emergency_state_query_without_argument_is_blocked.log`
- Автотест: `test_states.py::test_emergency_state_query_without_argument_is_blocked` (TC-ST-10)
- 2.3.0: `logs/v2.3.0/test_emergency_state_query_without_argument_is_blocked.log`

## Примітки
- Можлива інтерпретація: `state` без аргументу — безпечне читання. Але PRD називає список «тільки», тому потрібно або виправити код, або додати `state` до списку в PRD.
