# BUG-002 — `distance 20` відхиляється, хоча 20 — верхня допустима межа

| Поле | Значення |
|---|---|
| Версія, де знайдено | 2.1.0 |
| Відтворюється в 2.3.0 | **Так — регресія не усунена.** `distance 20` і далі дає `E704 count must be 1-20` на 2.3.0 |
| Severity | Minor |
| Priority | P3 (Medium) |
| Вимога PRD | DS-1: `distance <N>` — «N вимірів (**1-20 включно**) і середнє. Поза діапазоном — E704» |
| Тип | Функціональний, межа діапазону (off-by-one) |
| Відтворюваність | 3/3 |

## Передумови
- DUT 2.1.0, Wi-Fi підключено, `login` виконано, HC-SR04 підключено.

## Кроки відтворення
1. Виконати `distance 20`.
2. Для порівняння виконати `distance 19` і `distance 1`.

## Очікуваний результат
Виконується 20 вимірів і виводиться середнє. `E704` лише для N < 1 і N > 20.

## Фактичний результат
Відхилено з `E704`, а текст помилки сам називає 20 допустимим значенням:

```text
TX: distance 20
RX: E (13919) sentry: E704 count must be 1-20
```

## Докази
- `logs/v2.1.0/repro_run1/test_distance_count_range_20-None_.log` (+ run2, run3)
- Автотест: `test_boundaries.py::test_distance_count_range[20-None]` (TC-DS-02)
- 2.3.0: `logs/v2.3.0/test_distance_count_range_20-None_.log`

## Примітки
- N = 1 приймається, N = 0 і N = 21 коректно дають `E704`.
- Той самий клас дефекту, що BUG-001 і BUG-003: верхня/нижня межа «включно» реалізована як «строго».
